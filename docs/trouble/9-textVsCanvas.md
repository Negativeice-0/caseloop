Create a professional technical analysis canvas.

Canvas Type:
Software troubleshooting workspace.

Layout:
Use a clean infinite-canvas layout with interconnected cards and sections.

Sections:

1. Problem Statement
- Central card containing the observed error.
- Space for command output.
- Highlight failure indicators in red.

2. Evidence Collected
- Separate cards for terminal outputs.
- Repository configuration.
- Branch configuration.
- Remote configuration.
- Network observations.

3. Findings
- Convert evidence into validated findings.
- Use green checkmarks for confirmed facts.
- Use warning icons for assumptions or unknowns.

4. Root Cause Analysis
- Fishbone / cause-tree structure.
- Group causes by:
  - Network
  - Authentication
  - Repository
  - Branching
  - Local Environment
  - External Services

5. Diagnostic Workflow
- Decision tree format.
- Each node contains:
  - Test command
  - Expected result
  - Interpretation

6. Recommended Actions
- Ordered by probability and impact.
- Include quick wins, moderate fixes, and advanced diagnostics.

7. Conclusion
- Executive summary card.
- Confidence level indicator.
- Most likely root cause.
- Recommended next step.

Visual Style:
- Modern DevOps documentation board
- Dark theme
- GitHub-inspired colors
- Clean typography
- Connected nodes and arrows
- Terminal-style code blocks
- Technical architecture-diagram aesthetic
- Professional engineering incident-review format
- High information density without clutter

Output:
Generate a fully structured canvas with editable cards, connectors, callouts, status indicators, and notes suitable for collaborative troubleshooting sessions.
