# Frontend Audit Guidance

CaseLoop may change folder structures over time.

The audit should not rely exclusively on directory names such as:

- routes
- router
- pages
- features
- layouts

The import graph is the authoritative source.

When structures change:

1. Identify application entry points.
2. Verify App.tsx.
3. Verify main.tsx.
4. Follow application composition.
5. Confirm evidence before modifying scripts.

Folder names may change.

Application entry points are usually more stable.

Finding:
Phase 4 returned empty navigation and route evidence.

Investigation:
Frontend files existed and were confirmed through Phase 1.

Root Cause:
CaseLoop currently uses App.tsx composition rather
than dedicated router files.

Lesson:
Empty route evidence does not imply missing frontend.

Future Handling:
Review App.tsx and main.tsx first.
Update scan paths when architecture changes.
Record architecture discoveries in docs/knowledge/.
Do not modify the master prompt unless the methodology itself changes.
